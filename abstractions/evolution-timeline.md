# Evolution timeline

[Catalogue](../README.md)

A timeline connecting development events and decisions with changes to specifications and implementation.

| Property | Description |
| --- | --- |
| Subject | Project and process |
| Purpose | Descriptive, analytical |
| Required models | [Project model](../models/project.md), [History model](../models/history.md), [Code model](../models/code.md), [Physical model](../models/physical.md) |

## Developer question

How did the project reach its current state?

## Representation and interaction

Filter by time, feature, or artefact; compare revisions; inspect changed items and supporting decisions.

## Information and evidence

Revision metadata, file and declaration changes, and links to project items or documented decisions. The view should preserve navigation to supporting evidence and make unavailable information explicit.

## Example

A timeline shows the introduction of REQ-001, the decision to require confirmation, and the later implementation of TASK-008.

This example is illustrative.

## Limitations

Commit order records repository evolution, which may differ from when decisions were made. Do not infer undocumented rationale from a change alone.

## Scope

This entry describes an abstraction concept. It does not claim that a particular tool implements every interaction described here.
